# Contributing

1. Fork the repo and create a branch: `git checkout -b feature/short-name`.
2. Keep changes focused; open the file in a browser to test (no build step).
3. Follow existing style: 2-space indent, `camelCase` functions, comments for non-obvious logic.
4. Commit with clear messages (`feat:`, `fix:`, `docs:`).
5. Open a pull request describing what changed and why, with a screenshot for UI changes.

Bug reports and ideas: use the issue templates.
